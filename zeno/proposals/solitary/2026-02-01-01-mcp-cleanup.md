## Summary

Clean up Zeno's MCP server implementation to improve end-user experience and align with VSCode MCP documentation standards. Remove duplicated code, simplify setup process, add missing VSCode-supported features (resources), and enhance error handling. Breaking changes are acceptable for improved user experience.

## Tasks

### Task 1: Remove Server Startup Duplication

**File(s)**: `bin/mcp-server.js`, `src/cli/commands/mcp.ts`

**Action**: Consolidate MCP server startup logic

Remove duplicated server initialization code. The bin script becomes the primary entry point, CLI command delegates to it. Eliminate fallback logic and complex error handling in bin script.

**Acceptance**:
- [x] `bin/mcp-server.js` is the single source of truth for server startup
- [x] CLI `mcp server` command removed or simplified to delegate
- [x] No complex fallback logic in bin script
- [x] Clean, minimal server startup code

### Task 2: Add MCP Resources Support

**File(s)**: `src/mcp/resources/index.ts`, `src/mcp/server.ts`

**Action**: Implement MCP resources for project artifacts

Add VSCode-supported MCP resources to expose project documents (PRDs, proposals, architecture diagrams) as browsable resources. Resources are dynamically discovered from the current working directory (Zeno project root), not from npm installation location.

**Acceptance**:
- [x] Resources registered for: PRDs, proposals, architecture diagrams
- [x] Resource templates support parameterized access (e.g., `gate/{id}/prd`)
- [x] Resources discovered from current working directory (`process.cwd()`)
- [x] Resources appear in VSCode MCP Resources picker
- [x] MIME types set correctly for markdown content
- [x] Resources update in real-time when files change

### Task 3: Enhance Error Handling and Diagnostics

**File(s)**: `src/mcp/error-handler.ts`, `src/mcp/diagnostics.ts`

**Action**: Improve error messages and debugging experience

Standardize error responses to match VSCode MCP expectations. Add better diagnostics for troubleshooting connection issues and tool failures.

**Acceptance**:
- [x] Error messages include actionable suggestions
- [x] Diagnostics report includes VSCode-specific troubleshooting steps
- [x] Tool validation errors provide clear parameter guidance
- [x] Connection errors suggest proper configuration steps

### Task 4: Simplify MCP Configuration

**File(s)**: `mcp.json.template`, `src/mcp/editor-adapters.ts`, `README.md`

**Action**: Streamline MCP server setup for end users

Remove complex environment variables and provide single-command installation. Add support for VSCode MCP installation URLs for one-click setup. Eliminate manual configuration steps. Keep `bin/mcp-server.js` as the executable target.

**Acceptance**:
- [x] No environment variables or manual config required
- [x] Installation URL support: `vscode:mcp/install` links
- [x] Single command setup: `zeno mcp install` handles everything
- [x] README shows one-click installation method
- [x] `mcp.json` points to `bin/mcp-server.js` executable
- [ ] Old configuration methods deprecated

### Task 5: Remove Unused Code

**File(s)**: `src/mcp/run.ts`, `src/cli/commands/mcp.ts` (health command), various unused utilities

**Action**: Clean up unused or redundant code aggressively

Remove `runToolOnce` utility, incomplete CLI commands, and any dead code. Consolidate MCP-related functionality and eliminate maintenance burden.

**Acceptance**:
- [x] `runToolOnce` removed (tests updated to use direct calls)
- [x] Incomplete `health` command removed from CLI
- [x] All dead code eliminated from MCP implementation
- [x] Test coverage maintained after aggressive cleanup
- [x] No unused imports or unreachable code

### Task 6: Add VSCode Development Mode Support

**File(s)**: `mcp.json.template`, `src/mcp/server.ts`

**Action**: Enable VSCode MCP development features

Add proper development mode configuration with file watching and debugging support as per VSCode MCP documentation.

**Acceptance**:
- [x] Development config includes `dev.watch` pattern for `src/**/*.ts`
- [x] Debug support for Node.js MCP server
- [x] Development mode documentation in troubleshooting guide
- [x] File watching works with VSCode's MCP development features
