## Summary

Create a shared template loading utility that reads all Zeno templates from disk and registers them as callable functions in Zeno's function registry. This enables LLMs to access templates directly during workflow execution for gate generation, proposal creation, and documentation without requiring CLI invocation.

## Context

Zeno's Planner includes two categories of templates:
- **Markdown templates** (5 files): `agents-template.md`, `gate-prd-template.md`, `project-prd-template.md`, `proposal-template.md`
- **Architecture diagram templates** (11 files): System overview, gate roadmap, data flow, lifecycle, component, context, deployment, network, package, sequence diagrams

Currently, templates are static files with no programmatic access mechanism. LLMs have no structured way to request template content during workflow execution.

**Rationale**: Template loader infrastructure enables:
- LLMs to access templates as registered functions during gate generation and proposal creation
- Automatic validation that all templates exist on disk
- Consistent template access pattern aligned with Zeno's LLM-driven execution model
- Template content available for context without CLI overhead

## Implementation Notes

**Template Metadata Structure**:
```typescript
interface Template {
  name: string                    // e.g., "gate-prd-template"
  category: 'markdown' | 'architecture'
  path: string                    // Relative path from project root
  description: string             // Brief description for CLI help
  shortName: string              // e.g., "gate-prd" for display
}
```

**Markdown Templates List**:
- `agents-template.md` - AGENTS.md generation template
- `gate-prd-template.md` - Gate PRD document template
- `project-prd-template.md` - Project PRD document template
- `proposal-template.md` - Proposal document template

**Architecture Templates List**:
- `system-overview-template.md` - Component architecture diagram
- `gate-roadmap-template.md` - Gate progression diagram
- `data-flow-template.md` - End-to-end data flow diagram
- `lifecycle-template.md` - State machine / lifecycle diagram
- `component-diagram-template.md` - Component structure diagram
- `context-diagram-template.md` - Context / scope diagram
- `deployment-diagram-template.md` - Deployment architecture diagram
- `network-diagram-template.md` - Network topology diagram
- `package-diagram-template.md` - Package/module structure diagram
- `sequence-diagram-template.md` - Sequence / interaction diagram

**Path Resolution**:
Templates are located at `templates/[category]/[name]` relative to project root. Use `path.join(process.cwd(), 'templates', ...)` for file resolution.

**Caching Strategy**:
No caching needed. With only 16 templates, direct disk reads are efficient and keep implementation simple.
